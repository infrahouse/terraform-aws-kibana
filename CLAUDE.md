existing Elasticsearch cluster.

## Architecture

This is a thin composition module — it has almost no resources of its own. Instead it wires together three published
InfraHouse registry modules:

- **`main.tf`** — the core `module.kibana` (source `registry.infrahouse.com/infrahouse/ecs/aws`, pinned to a major
  version). It runs the official `docker.elastic.co/kibana/kibana` image as an ECS service behind a load balancer, on
  an EC2-backed ASG. Kibana is configured entirely through `task_environment_variables` (server URL, Elasticsearch
  hosts/username, request timeout) and `task_secrets` (encryption keys, Elasticsearch password). Container listens on
  port 5601; health check hits `/status`, ALB health check hits `/login`.
- **`secrets.tf`** — two `module.kibana-*` instances (source `infrahouse/secret/aws`) store the Kibana encryption key
  (a `random_string`) and the `kibana_system` password in Secrets Manager. The ECS task execution role is granted
  reader access.
- **`iam.tf`** — an IAM policy (`task_role_exec`) granting `secretsmanager:GetSecretValue` on those two secrets,
  attached to the ECS task via `execution_extra_policy`.
- **`datasources.tf`** — resolves the Route53 zone, the first ASG subnet, and its VPC.

Data flow: `kibana_system_password` (input) and a generated encryption key flow into Secrets Manager → exposed to the
container as `task_secrets` → the task execution role reads them at launch.

### Dual AWS provider

The module requires **two AWS provider configurations**: `aws` (default) and `aws.dns` (passed through to the ECS
module for Route53 DNS records). Callers must supply both in their `providers` block.

### Versioning

The version lives in **three places that must stay in sync**: `.bumpversion.cfg` (`current_version`), `locals.tf`
(`module_version`), and `README.md` (the `version = "x.y.z"` in the usage example). Use
`make release-{patch,minor,major}` rather than editing these by hand — it runs `git-cliff` to update `CHANGELOG.md`,
then `bumpversion` to update all three and create the git tag. Releases must be cut from `main`.

## Commands

```bash
make bootstrap     # install Python deps (pytest-infrahouse, infrahouse-core)
make lint          # terraform fmt -check + black --check tests
make fmt           # terraform fmt -recursive + black tests
make test          # pytest -xvvs tests/  (no AWS args; see below)
make test-keep     # run integration test, KEEP the AWS resources for debugging
make test-clean    # run integration test, DESTROY resources after (use before PR)
```

Run a single AWS provider variant by overriding the selector, e.g.:
`pytest -xvvs --aws-region=us-west-2 --test-role-arn=<arn> -k aws-6 tests/test_module.py`

## Testing

Tests are **real integration tests** — they call `terraform apply` against live AWS, not mocks. `tests/test_module.py`
is parametrized over AWS provider versions (currently just `~> 6.0`, id `aws-6`). The test:

1. Stands up dependencies via `pytest-infrahouse` fixtures (`elasticsearch`, `service_network`, `subzone`) — Kibana
   cannot be tested in isolation because it requires a running Elasticsearch cluster.
2. Generates `test_data/kibana/terraform.tf` (provider pin) and `terraform.tfvars` at runtime from fixture outputs.
3. Applies `test_data/kibana/`, which calls this module via `source = "../../"`.

The default test role and region are baked into the `Makefile` (`TEST_ROLE`, `TEST_REGION`); they target a dedicated
tester AWS account. Running tests requires AWS credentials able to assume that role. `make test-keep`/`test-clean` tee
output to a timestamped `pytest-*-output.log` (these logs are gitignored cruft; don't commit them).

## Conventions

- **Commit messages** use Conventional Commits (`feat:`, `fix:`, `docs:`, etc.) — `git-cliff` consumes them to build
  the changelog, so the prefix matters. A `commit-msg` hook enforces this; `pre-commit` runs formatting checks.
  `make install-hooks` (run automatically by `make help`) symlinks them in.
- The `<!-- BEGIN_TF_DOCS -->`/`<!-- END_TF_DOCS -->` block in `README.md` is auto-generated by terraform-docs (config
  in `.terraform-docs.yml`) — don't hand-edit it.
